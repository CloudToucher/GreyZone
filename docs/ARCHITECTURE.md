# 主持权与桌务边界

AI 掌握裁决权：行动可行性、是否掷骰、专长和环境是否适用、NPC 的意图、时间跨度、战斗顺序、伤势影响及实际后果。人物、能力、关系、制造方法和局部先例都是资料，不为每种玩法新增程序分支。

代码掌握不可含糊的事项：随机数、属性与修正计算、资源非负、物品数量和归属、权限、幂等性、原子提交、视野投影。代码不能凭一句玩家输入决定敌人反击，也不要求模型提前填写成功/失败两套文本。

## 一轮的数据流

```mermaid
flowchart LR
  P[玩家意图与条件] --> B[行动板]
  B -->|房主发起，冻结批次| R[唯一活动裁决]
  R --> C[权威局势与未决事项]
  C --> D[dsh 持续 GM 会话]
  D <-->|原生 MCP| T[查询、真骰子、工作草稿]
  T -->|阶段提交：叙述与状态同一事务| S[(SQLite)]
  S --> V[按席位过滤]
  V --> W[网页团录、人物、物品、地图]
```

`Campaign.world` 是已提交的权威状态；`Run.draft` 是唯一在途工作状态。`state_apply` 不向网页暴露草稿。`turn_commit` 同时更新世界版本、账目、叙述、行动结果和检查点，再通知 SSE。多人后续行动仍可写入下一批，提交不会丢失这些输入。

骰子立即单独落库，绑定 run、check ID 和依据指纹。批量调用后续部分即便失败，也不能抹掉先前已产生的骰子。恢复会带上原结果。结算回执按“裁决 + 工具名 + key”区分；同一工具同 key 的不同内容被拒绝。

每桌一个原生运行队列。提问后的快速回答、上次发布后立即开始下一批，都排到前一原生调用真正退出之后；同一恢复代次重复请求被合并。MCP 绑定正在执行的 run，而不是随时查询“最新活动轮”，防止上一轮的迟到调用误写下一轮。

## 记忆

Markdown 是规则与世界背景；SQLite 中的事实、关系、目标、地点、承诺和裁定是战役当前状态。`fact / relation / ruling / clock` 只是常用资料种类，`data` 可扩展。系统记录对象索引、结构化引用、修改时间与变更原因。索引可从权威资料重建，不成为第二份账本。

位置变化的阶段时段自动写入审计，并作为 recentMovements 提供给主持。它用于核对连续性，不自动推断旅程的每一分钟。具名人物、地点和势力的重复创建会被拦截；同名不同对象可说明区别，误建副本用 aliasOf 留痕归并，不能生成第二份资产。

每轮自动提供参与角色、现场、装备、开放事项、到期事项、最近叙述、草稿变化和已掷骰。定向搜索返回片段，再按 ID 读取需要的全文。模型只写有意义的增量，不抄角色表和日志。dsh 压缩保留因果与未决事项，账目以恢复时注入的 SQLite 数据为准。

## 视野和权限

记录和叙述采用 `audience=[]`（GM）、`['table']`（全桌）或角色 ID 列表。`secret` 永不投影。公开 `data` 只写已知信息；不知道的动机和真相放 `secret` 或独立私密记录。地图中的隐藏记录引用也会过滤。暗骰、工具参数、提示词、错误详情和账目内部原因不下发客户端。

建角、私密讨论的回复范围被服务端约束；建角不能修改其他角色或世界。角色采用与托管只能由所有者操作。分队叙述由 AI 按实际知情范围选择接收者，程序严格执行该范围；文本本身的知情合理性仍需主持判断，不能靠字段权限理解一切秘密。

## 故障边界

SQLite WAL 与事务保证发布原子性；单写入文件锁防止第二个服务把正在运行的裁决误判为崩溃。原生会话在建成时立即 flush。暂停调用 dsh `cancel` 后终止进程；异常退出保留草稿、回执和检查点。恢复重新注入权威状态并沿用 session ID。

模型超时或工具错误不会替它发布虚构结局。网页显示可恢复的失败；本地诊断供运行者查阅。新档案格式不承诺旧版本迁移。首版不含公网账户服务或多服务实例集群。
